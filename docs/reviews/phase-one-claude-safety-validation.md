# Phase 1c: provider correctness and interaction safety

PR #39 extends the original seven-record Claude batch to the full provider-correctness workstream, based on merged PR #37 (`8e3d9acc4c`). The audit covers all 77 records originally assigned to 1c: **44 ported, 21 equivalent, five not applicable, and seven retained for later phases**. The September classification file remains the original review artifact; the single ledger records these subsequent decisions.

## Behavior

- Claude metadata runs in a scoped temporary directory with hooks, ordinary tools, slash commands and implicit MCP configuration disabled, without skipping permissions. Object/array envelopes, image-first input, SDK-suggested session-scoped permissions, refusal warnings and probe isolation are covered. Stop serializes with sending, closes the query, cancels pending interactions and stops background tasks; follow-up sessions retain their resume cursor. SDK session-only grants end with the stopped process and are not replayed. Early child model snapshots are preserved without leaking child text into the parent transcript.
- Codex approval details include up to 20 paths. Memory-consolidation threads cannot replace the primary session or populate its transcript. Missing rollouts use the resume fallback; rate-limit and auth failures do not. MCP app approvals expose only representable schema choices, including explicit persistent consent. Arbitrary forms and URL requests cannot be accidentally accepted. Provider-reported subagent models reach the Agents panel.
- Cursor transport diagnostics fail the turn; ordinary quoted diagnostics and internal agent messages remain content. Session notification consumers survive their startup request. Runtime modes select the corresponding CLI permission flags. Skill discovery follows linked packages with bounded traversal and cycle detection, and supports digit-leading names. Editor launches use `--classic`.
- ACP drains bounded stderr into exit errors, accepts the SDK elicitation alias, bounds tool text and coalesces redundant progress without dropping terminal or background-start events.
- Grok uses bounded version/model health probes rather than launching an ACP login flow. Background monitor/shell tasks have explicit lifecycles. Stop tears down the session; callbacks from older prompts cannot mutate replacement sessions.
- OpenCode merges the effective instance configuration, reads workspace skills through the SDK, bounds CLI probes, and preserves workflow permission restrictions. Full-access approvals reply once, including verified child sessions. Successful replies resolve locally; failed replies remain retryable. Stop aborts the parent and descendants, and clears the active turn without requiring a later idle event. Stream termination fails the session. Revert/readback group assistant steps by their user prompt and target the first removed user message.
- Failed provider interruption falls back to stopping the same active session, with stale-turn checks. Windows PATH normalization, reasoning labels, the Codex trait chevron and Claude Insight line breaks are included.

## Compatibility and scope

Protocol version **3** gates the added MCP request/decision variants and task-model metadata. Existing tabs follow the protocol upgrade flow. No database migration, automatic provider installation, settings-default change or account sharing is introduced. f5 model catalogs and aliases, workflow/Plan permissions, profile isolation, durable queue and compaction remain authoritative.

The verify-first Claude records were resolved separately: hard stop is implemented and tested; empty-home continuation identity already resolves through f5's canonical home helper. The upstream permission-argument override is not adopted because it conflicts with f5's reserved permission arguments. The upstream quadratic Codex parser fix remains unnecessary because f5 already reads line-delimited output.

The native f5 subagent stream differs from upstream's synthetic CollabRuntime. Reported model metadata is preserved, without adding a second child-thread discovery bridge. A native `interacted` event still resumes agent activity; the upstream bug from synthesizing that event while merely reading an idle child does not apply here.

Seven records remain explicit future work, not shipped ports: five provider installer/update fixes in **Phase 14**, Azure DevOps discovery budgeting in **Phase 12b**, and backslash citation paths in **Phase 3e**, which needs the corresponding citation renderer. These assignments correct dependencies in the initial 1c bucket; the overall upstream program is unfinished.

## Review follow-up (2026-09-25)

All twelve findings received code changes and regression coverage where practical:

- Claude no longer invents a tool-wide rule when suggestions are absent. Interrupt takes the thread lock, stale turn IDs fail explicitly, and send checks whether its context stopped while awaiting setup. Hard Stop intentionally clears process-local grants; it preserves the conversation resume cursor, not SDK permission memory.
- MCP app approvals require recognised consent controls with anchored choice matching. Hidden optional fields and defaults are never submitted. Session persistence cannot advertise permanent consent. Unsupported data forms are cancelled with a warning before creating an approval request.
- OpenCode marks interrupt intent before HTTP calls, so racing idle/error events emit aborted instead of completed. Parent abort failures remain errors; child-discovery limits or failures warn without blocking successful interruption. Discovery ignores historical children not observed in the current turn when timestamp evidence exists. Permission handling checks stopped state before auto-reply. Rollback targets complete user turns, including multi-step assistant responses.
- Grok guards late callbacks by context identity rather than reusable native session IDs. Interrupting idle Grok sessions is a no-op. Provider routing does not recover idle/stopped sessions for Stop and rejects unsupported persistent-consent decisions before recovery. Recovery of a persisted running turn remains supported, since it is needed to reconcile an orphaned turn.
- Cursor always drains queued notifications before interpreting a transport diagnostic, even with ACP hardening off. A failed provider turn returns its accepted submission identity instead of reporting ambiguous delivery. Skill discovery stops at the first SKILL.md in a package.
- ACP output bounding includes Grok Result.output and MultiResult results, preserving task metadata.

Regression cases cover missing Claude suggestions, hidden/default MCP fields and broad enum choices, session-only persistence, idle/error during OpenCode abort, oversized/unavailable child discovery, late permission events, mixed user/assistant rollback, reused Grok session IDs, idle Stop, concurrent Claude send/Stop, default Cursor diagnostic handling, nested skills and nested output. The requested full Phase 1c PR remains together; no history rewriting or PR split was performed.

Review follow-up validation: `bun fmt`, `bun lint`, `bun typecheck`, the full workspace suite (2,567 server unit tests and 16 server integration tests), all 131 exhaustive Git tests, and all 431 browser tests pass. Online ledger validation remains mandatory. Lint retains nine existing warnings and zero errors; opt-in live-provider tests remain skipped.
