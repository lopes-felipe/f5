# PR #21 review disposition

The review identified real correctness and confidentiality defects. Several findings also contradicted explicit choices in the approved plan or overlooked existing code. The changes below retain isolation for non-default profiles while restoring Default's host Git and account compatibility.

| Finding                                            | Disposition                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1: Default Git/GitHub compatibility                | Fixed. Default preserves host Git settings, repository-local author, SSH and credential helpers. Its GitHub API falls back to ambient credentials and `gh auth` when no saved profile token exists. Non-default profiles remain isolated. Tests cover host configuration, real commits, SSH acceptance and the legacy gh login. |
| 2: Default fallback port                           | Fixed. Automatic fallback no longer updates the registry or retires Default's recorded port. An explicit Settings port change still retires the previous port. A regression checks byte-identical registry contents after fallback.                                                                                             |
| 3: Browser cookies                                 | Fixed. Cookies include the stable profile ID. Two real authenticated backends on one hostname are covered by the lifecycle smoke, including independent logout.                                                                                                                                                                 |
| 4: Renderer argv token                             | Fixed. Arguments contain only the profile ID. The owning main-frame preload obtains its URL through sender-bound IPC, preserving the existing synchronous bridge API without exposing credentials in argv.                                                                                                                      |
| 5: Preview discovery                               | Retained intentionally. The plan explicitly removed machine-wide scanning because it exposes unrelated processes to remote clients. The empty-state UI and changelog now explain manual URLs and restart behavior, including Default.                                                                                           |
| 6: CI build dependency                             | Not a defect. `apps/desktop/turbo.jsonc` already declares `smoke-test` dependencies on desktop, web and server builds. The lifecycle step follows it. The review inspected only the root `turbo.json`.                                                                                                                          |
| 7: Interrupted provisioning                        | Fixed. Stale provisioning is rolled back even when settings were written; partial data is moved to trash under the instance lock. A regression covers that crash window.                                                                                                                                                        |
| 8: Desktop reopen                                  | Fixed. Concurrent opens are coalesced before allocation. Stopped runtimes retain port/token identity, so all retained windows reconnect to the same endpoint; opening no longer replaces only the first window. Failed allocations can be retried.                                                                              |
| 9: Default environment validation                  | Fixed. Reserved account-home overrides are rejected only for non-default profiles, both at execution and settings save. Default instance and terminal overrides remain supported.                                                                                                                                               |
| 10: Mutable credential helper                      | Eliminated the mutable file. Git executes bundled helper source directly, with credentials only in the environment and host matching retained. There is no helper file to replace or symlink.                                                                                                                                   |
| 11: Logout handle and lease root                   | Fixed. Logout returns a handle and uses the same input/cancel panel as login. Account operations require installation metadata instead of deriving a per-profile OAuth lock root.                                                                                                                                               |
| 12: Claude home override                           | The wire schema has no Claude home field, so the described client bypass did not exist. Added defensive rejection for internal callers and documented the adapter's spawning entry points. A test checks both boundaries.                                                                                                       |
| 13: Account-terminal confidentiality               | Fixed. Output is sent only to the initiating socket; input and cancellation validate connection ownership. Disconnect cancels that connection's jobs before releasing their leases.                                                                                                                                             |
| 14: Shell startup                                  | Retained the approved no-rc-file policy. Preserved other resolver arguments and documented PATH/toolchain setup. Automatically sourcing external files would defeat the isolation boundary. Default shell behavior is unchanged.                                                                                                |
| 15: Repeated certification / MCP instance fallback | Fixed. Certification coalesces requests and caches successful checks for one minute, keyed by profile, executable and execution environment, with bounded storage. MCP selects an existing conventional instance or the sole matching instance; ambiguous requests require selection.                                           |
| 16: Health probes / duplicates                     | The probes were not removed: Cursor and OpenCode drivers still execute their own checks. Fixed the real issue: the legacy driver-keyed health response now deterministically emits one entry per driver. Instance-aware UI retains the complete snapshots.                                                                      |
| 17: Certification pins / bundling                  | Added a manifest equality test and a static JSON import. The built-server smoke invokes isolated bundled Claude account status and verifies a fresh home is unauthenticated. Version changes still require deliberate recertification, as the plan requires.                                                                    |
| 18: Project-event amplification                    | Fixed. The handler runs after sequence rejection, warnings are scoped to the affected root, and profile inspection is cached for two seconds with invalidation on project/registry/account changes.                                                                                                                             |
| 19: MCP error attribution                          | Fixed. Only acquisition errors are labeled as lease failures; other failures retain their underlying cause.                                                                                                                                                                                                                     |
| 20: Retention                                      | Successful startup clears its stale error file. Trash and retired ports remain intentionally retained for recovery and browser-origin safety; lock metadata remains to avoid changing the lock inode under another process. Documented disk reclamation and retention explicitly rather than introducing automatic deletion.    |
| 21: Explicit telemetry overrides                   | Fixed. Inherited OTEL variables are filtered; deliberately configured overrides are honored.                                                                                                                                                                                                                                    |

Additional fixes: corrected window-title punctuation, threaded `defaultStateDir` rather than reversing a path suffix, normalized the GitHub hostname input, clarified the verification destination, tolerated missing installation identity during backup with a fresh unverified source identity, and recognized structured SQLite busy codes.

The nine-minute MCP timeout is intentional: it leaves teardown time inside the ten-minute shared login budget and is now documented. GitHub Enterprise hostnames remain explicitly user-selected; restricting them to a public-host allowlist would remove enterprise support. Port allocation retains the required lowest-bindable-port algorithm under the registry lock; no performance evidence justified replacing it.

Restoring host behavior also exposed test fixtures that inherited Windows line-ending configuration or the developer's gh login. The server test environment now isolates those defaults; tests that exercise host compatibility supply their configuration explicitly. This changes test isolation, not Default's runtime behavior.
